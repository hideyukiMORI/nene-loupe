## 文脈

NeNe Loupe は未署名の portable ZIP を GitHub Release で配っている。未署名なので、利用者には
SmartScreen の「発行元不明」の警告が出る。公式の説明では、未署名のファイルの評判は版を出すたびにゼロから始まり、
Windows 11 の Smart App Control は未署名のファイルの実行そのものを止めることがある。

hide は「ほぼ完成しているので、どこかで公開したい」と言っている（2026-10-03）。
前提を一次資料で確かめ、実機で測った。詳細と出典は
[調査報告](../reports/2026-10-03-store-msix-research.md)にある。要点は次のとおり。

| 確かめたこと | 結果 |
| --- | --- |
| Store に MSIX で出すと Microsoft が署名するか | する。認定後に Microsoft の証明書で署名し直す。自前の証明書は不要 |
| 個人の開発者登録の費用 | 無料（`storedeveloper.microsoft.com` から入った場合） |
| Store から入れたアプリの SmartScreen | 警告は出ない |
| MSI/EXE で Store に出す場合 | 自前の署名と自前のホスティングが必須 |
| いまの exe を MSIX に包めるか | 包めた。製品コードの変更なしで、起動・採取・キャプチャ除外・複写が通った |
| 設定の保存先 | 初めて入れた人はパッケージ専用の場所になる。ZIP 版の設定がある人はそれを引き継ぐ |
| アンインストール | Store 版が作ったものは残らない |
| 版 | Store は先頭が 0 の版を受け付けない。いまは `0.2.0` |
| プライバシーポリシー | Win32 を包んだ製品は常に必須 |

## 決定

**配布経路に Microsoft Store（MSIX）を足す。portable ZIP は残す。MSIX は Store への提出物としてだけ作り、GitHub Release には載せない。**

- ZIP は「入れたくない人・Store を使えない人」の経路として残す。中身と作り方は変えない。
- MSIX は ZIP と同じ exe から作る。`eng/package-release.ps1` が検査を終えた `out/release/stage/NeNeLoupe.exe` だけを
  `eng/package-msix.ps1` の入力とし、MSIX のために再ビルドしない。exe を作る経路は 1 本のままである（ARC-001）。
- 版の入力は `CMakeLists.txt` の 1 か所のままとする。MSIX だけ別の版を持たない。Store が先頭 0 を受け付けないので、
  Store に出す最初の版で製品の版を 1.0.0 以上へ上げる。
- 署名は Store に任せる。自前の証明書は買わない。
- `Identity/Name`・`Identity/Publisher`・`PublisherDisplayName` は Partner Center が決める値を使う。
  いまのスクリプトの既定値は手元の検証用で、提出には使えない。

受理のあとに、別の Issue で行う作業（この ADR では行わない）:

1. 製品の版を 1.0.0 以上へ上げる。
2. プライバシーポリシーをリポジトリに置く。
3. 掲載用のスクリーンショット（1366×768 以上）を作る経路を決める。ADR 0007 の撮影経路の続きになる。
4. ロゴ一式（倍率別・`targetsize` 別）と `resources.pri` を作る。
5. Windows App Certification Kit を通す。
6. README と `docs/release/README.txt` に、Store 版では設定の場所が違うことを書く。
7. DEVELOPMENT_WORKFLOW 第 9 節に Store への提出の手順を足す。

## 強制

受理はしたが実装は Issue #38 で行うので、**いま active な強制は無い。** `eng/package-msix.ps1` はゲートの外にある実測用の道具である。

| 守りたいこと | 状態 | active にする条件 |
| --- | --- | --- |
| MSIX の exe は Release の正規経路が作ったものである | planned | スクリプトは入力を `out/release/stage/NeNeLoupe.exe` に固定している。Issue #38 で、`package-release.ps1` から続けて呼ぶ形にし、ZIP の中の exe と MSIX の中の exe のハッシュが同じであることを検査する |
| Store に出す版の先頭が 0 でない | planned | いまは警告を出すだけ。Issue #38 で、提出用の作成では失敗にする |
| 証明書と鍵をリポジトリに入れない | planned | いまは「ファイルを作らない」運用（証明書ストアの拇印で指す）と `/out/` の除外だけ。Issue #38 で、`.pfx` / `.cer` / `.pvk` を拒否する検査を規約検査に足す |
| マニフェストの身元が Partner Center の値と一致する | 不能 | 値は Partner Center の中にあり、リポジトリからは確かめられない。提出時に Partner Center が拒否する |
| 審査に通ること・Store が署名すること | 不能 | Microsoft の側で行われる |

## 結果

得られるもの:

- Store から入れた人には SmartScreen の警告が出ない。証明書の費用と管理が要らない。
- 更新が Store から自動で届く。アンインストールで何も残らない。
- winget の `msstore` ソースからも入るようになる（`microsoft/winget-pkgs` への提出は要らない）。

失うもの・増えるもの:

- 版を出すたびに Store への提出と審査（3 営業日まで）が要る。配布物が 2 つになり、公開の手順が増える。
- hide の本人確認と、個人名での発行者名の登録が要る。発行者の表示名は、後から変えられない前提で決める必要がある。
- プライバシーポリシー・掲載文・スクリーンショット・年齢区分の回答を維持する必要がある。
- 設定の場所が入れ方で変わる。ZIP 版と Store 版を併用する人の設定は、状況によって共有されたり別々になったりする。

残る穴（正直に）:

- **審査に通るかどうかは分からない。** 規約には画面の画素を読むことへの条項が無く、`runFullTrust` の判断基準も公開されていない。
  窓が画面の取り込みに映らない（ADR 0005）ので、審査員が普通の道具で動作を確かめにくい可能性がある。審査員向けの注記で説明するしかない。
- **実測したのは自己署名のパッケージである。** Store が署名したものの挙動は、提出しないと測れない。
- 実測は Windows 11・144 DPI・モニタ 1 枚だけ。Windows App Certification Kit は回していない。
- 発行者の表示名を後から変えられるかは、公式文書が食い違っていて確定できない。
- 個人の本人確認にかかる日数は文書に無い。
- 規約は 7.20（2026-10-22 発効）を読んだ。規約は変わるので、申請の直前に読み直す必要がある。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| いまのまま（未署名の ZIP だけ） | 警告が消えない。評判は版ごとにゼロから始まる。Smart App Control で実行を止められることがある |
| OV / EV のコード署名証明書を買う | 公式の表で年 300〜500 ドル。公式の説明では、EV でも初回の警告は出る。評判が貯まるまで警告は続く |
| Azure Artifact Signing（旧 Trusted Signing） | 公式の説明では、個人が使えるのは米国とカナダだけ。日本の個人は対象外。使えても初回の警告は出る |
| MSI / EXE のまま Store に出す | 自前の署名と自前のホスティングが必須。Loupe はインストーラを持たないので、作るところからになる |
| 自己署名の MSIX を GitHub Release に載せる | 実測で、利用者が管理者権限で証明書を入れない限り入らなかった（`0x800B0109`）。配布の手段にならない |
| ZIP をやめて Store だけにする | Store を使えない環境・入れたくない人の経路が無くなる。hub の指示書も ZIP を残す前提 |
| MSIX だけ別の版番号にする（`0.2.0` を `1.2.0.0` と読み替える等） | 版の入力が 2 つになる（ARC-001）。利用者に見える版と Store の版が食い違う |
| MSIX のために exe を別にビルドする | exe を作る経路が 2 本になる。検査を通っていない exe が配布物に入りうる |
| winget（`microsoft/winget-pkgs`）へ ZIP を出す | 今回は決めない。未署名の MSIX は受け付けない。ZIP は形式としては出せるが、検証で止まるかどうかを文書から判断できなかった。Store に出れば `msstore` から入る |
