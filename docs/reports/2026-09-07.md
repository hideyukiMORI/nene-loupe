## 撮影経路の実測

ルーペ窓と設定窓は`WDA_EXCLUDEFROMCAPTURE`を掛けている（ADR 0005）ため、
一般の撮影経路では1枚も撮れない。どれが通るかを推測せず、1本ずつ測った。
スクリプトと生の結果は`out/readme-capture/probe*.py`と`probe*-results.json`にある。

| 経路 | 実測結果 |
| --- | --- |
| `PrintWindow(hwnd, dc, PW_RENDERFULLCONTENT)` | 戻り値TRUE、画像は全面#000000 |
| `PrintWindow(hwnd, dc, 0)` / `PW_CLIENTONLY` | 戻り値TRUE、DCに何も描かれない（番兵の色が残る） |
| 画面DCからの`BitBlt` | 背面だけが写り、窓は写らない（除外の設計どおり） |
| 別プロセスからの`GetWindowDC`＋`BitBlt` | `BitBlt`がFALSE |
| 別プロセスからの`SetWindowDisplayAffinity(hwnd, 0)` | FALSE、`GetLastError()`=5（アクセス拒否） |
| 製品に`WM_PRINTCLIENT`を実装して`PrintWindow` | 効果なし。除外された窓では窓プロシージャに届かない |
| 除外を掛けない同じ窓を別プロセスから`PrintWindow` | flag 0/1/2すべて正しい内容を返す |
| 除外を掛けない窓を別の窓で覆って`PrintWindow` | 隠れていても正しい内容を返す |
| 除外を外した窓の中心を画面DCから読む | 背面の#FF8000ではなく窓自身の#00CC00 |

`WM_PRINTCLIENT`は製品へ実装して測ったうえで捨てた。除外の有無だけで結果が変わることから、
塞いでいるのはプロセス境界ではなく除外そのものであり、製品側に描画の口を足しても通らない。
最終行は施主の懸念の実測で、ルーペの採取点はレンズ中心（クライアント32 DIP）で必ず自窓の内側にあるため、
「レンズ直下に自窓が来ない配置」は存在しない。

## 決めたことと変更したもの

取り込み除外を閉じた選択肢`CaptureExclusion`（`enabled` / `disabled`）にし、
文書化した診断用の起動引数`--allow-screen-capture`のときだけ`disabled`にする。
**既定の起動は何も変わらない。**

| 対象 | 振る舞い・変更 |
| --- | --- |
| `src/core/CaptureExclusion.{hpp,cpp}` | 閉じた選択肢と、引数解釈の唯一の場所`capture_exclusion_of` |
| `src/ui/win32/CaptureExclusionStyle.{hpp,cpp}` | Win32の表現への唯一の変換。網羅switch |
| `LoupeWindow` / `SettingsWindow` / `PopupCaptureExclusion` | 同じ値を通すだけ。3種類の窓が1つの判断を共有する |
| `src/app/Main.cpp` / `CMakeLists.txt` | `wWinMain`のコマンドラインを合成ルートで解釈、ソース登録 |
| `tests/unit/LoupeTests.cpp` | 引数解釈の8件（空・空白・単独・前後空白・並び・タブ区切り・前方一致2種） |
| `eng/capture-readme-images.py` | 撮影スクリプト。製品側に画像書き出しの口は作っていない |
| 文書 | ADR 0007と索引、SPECIFICATION FR-017、GLOSSARY、README、現在タスク |

撮影スクリプトはルーペの上に背景窓を最前面で重ね、レンズ直下の7×7画素を描いてから
`PrintWindow(PW_RENDERFULLCONTENT)`で撮る。ルーペは自窓ではなくその背景を採取する。
**窓自身の題名が、スクリプトの描いた中心画素のHEXと一致した画像だけを保存する。**
自窓の像をREADMEへ載せないための歯止めで、ゲートではなくスクリプトの歯止めである。

## 残件と残るリスク

- 本日報はPR #22の統合後に書いたため、[Issue #23](https://github.com/hideyukiMORI/nene-loupe/issues/23)と対応PRで記録する。
- 製品に、普通の利用者には要らない起動引数が1つ残る。ADR 0007がその存在の唯一の根拠である。
  引数を渡した起動では3種類の窓が画面共有に映り、レンズは自窓を採る。仕様どおりの帰結で、機械では防げない。
- READMEの画像がUIの変更に追随しないことを機械は検査しない。`eng/check.ps1`は画像を作らない。
- 撮影は120 DPIと144 DPIのみ。96 DPIの実測は無い。
- 雛形（`INIT_PROCEDURE` Phase 4）への還流点: ①撮影経路は実測してから選ぶ、
  ②取り込み除外を持つアプリでは〈文書化した診断用引数＋自窓を覆う背景窓＋`PrintWindow`〉が
  実測で通る形、③採用条件を「窓自身が出す値と撮影側が描いた値の一致」に置く。
