## 3. 案 B を採った理由

1. **採取契約に触れない。** 高さ 64 と 7×7 @ 8 倍が変わらないので、ADR 0004 / 0005 と
   `ScreenSamplerPort` の契約、覗いている対象を隠す走査線の本数がそのまま。増えるのは幅だけ。
2. **色番号がこの道具の成果物。** 等幅 15 DIP なら 30 ms ごとの再採取で桁が踊らず、
   閉じた集合の最長も 24 DIP の余りを残して入る（第 2 節の実測）。
3. **ドラッグとクリックが場所で分かれる。** 左 86 DIP（レンズ＋色板＋余白）が丸ごと握りになる。
   レンズは「狙いを付ける部分」なので、そこを掴んで動かすのは操作として自然で、
   掴める場所を探さずに済む。案 A は分ける余地が無く、案 C は握りが分断される。
4. **コピー通知を、値を隠さず、位置もずらさずに置ける。**

**代償**（キャンバスにも書いた）: 3 案でいちばん幅を取る（現状比 +50%）。
通知のために右上へ 54 DIP を常時空けるので、通常状態では余白に見える。

## 6. 状態

`LoupeController` が持つ最新の結果と、UI 側の一時状態の掛け合わせ。
キャンバスの `StatesDark` / `StatesLight` に 2 倍拡大で並べてある。

| 状態 | レンズ | 色板 | チップ | 値の行 | 通知欄 |
| --- | --- | --- | --- | --- | --- |
| 通常 | 画素 + 中心印 | 中心色 | 面 + 枠 | 値（文字色） | 空 |
| 値にポインタ | 同上 | 同上 | 同上 | ヒット矩形を面で塗り 1 DIP の枠 | 空 |
| チップにポインタ | 同上 | 同上 | 面・ホバー | 通常 | 空 |
| **コピー直後** | 同上 | 同上 | 同上 | 値 + 下線（強調 2 DIP） | チェック +「コピー」（強調） |
| **採取失敗** | 面で平塗り・中心印なし | 面 | 地 + 枠、文字・淡（無効） | 警告帯 + 失敗文言（文字・淡） | 空 |

- コピー通知の表示時間は **約 900 ms**。
- 失敗時は `LoupeFrame` が画素を捨てるので、**古い画素を残さない**（ADR 0004 の判断そのまま）。
  失敗中はコピーと形式切替のヒット矩形を無効にする。ギアは有効のまま。
- 失敗文言は `LoupeFrame::from_sample` が作る文字列をそのまま出す。**UI は理由を解釈しない。**

### コピー通知の所有者について（設計上の注意）

「コピーしてから何 ms 経ったか」を UI が時刻の差で判断すると、`ui/win32` が実時刻を読むことになる（ARC-007 違反）。
**`WM_TIMER` を 1 回張って、発火で「コピー確認中」フラグを落とす**形にする。
既存の 30 ms タイマと同じく、タイマは*きっかけ*であって値の正本ではない（ADR 0004）。
フラグの所有者は `application`（`LoupeController` か、その隣の表示状態）に 1 つ。

## 7. ヒット領域と、ドラッグとクリックの弁別

現状は全面 `HTCAPTION`。操作部を足したら、**次の 3 矩形だけ `HTCLIENT` を返す。**
残りは `HTCAPTION` のまま。キャンバスの `HitAreas` に重ね図がある。

| 操作 | 矩形 (l,t,r,b) | 大きさ |
| --- | --- | --- |
| 形式チップ | 86,3,150,27 | 64 × 24 |
| ギア | 211,3,238,27 | 27 × 24 |
| 値・コピー | 86,29,238,61 | 152 × 32 |

- 3 矩形は重ならない（チップ下端 27 / 値上端 29、チップ右端 150 / ギア左端 211）。
- 高さはいずれも **24 DIP 以上**。Windows のコンパクト系コントロールと同じ寸法。
  マウス前提のデスクトップ小物なので、モバイル指針の 44 px は採らない。
- 窓の下端に **3 DIP（y 61〜63）の掴める帯**を残してある。値の行の下でも掴める。
- ドラッグ用に残る面積: 左 86 × 64 DIP（レンズ + 色板 + 余白）＋ 上下端の帯。

### クリックとドラッグを取り違えない

`HTCLIENT` の矩形の上では OS がドラッグを面倒みてくれない。次のようにする。

1. `WM_LBUTTONDOWN` で `SetCapture`、押した点を覚える。
2. `WM_MOUSEMOVE` で、`GetSystemMetrics(SM_CXDRAG)` / `SM_CYDRAG` を超えて動いたら
   **クリックを取り消し**、`ReleaseCapture` して
   `SendMessageW(hwnd, WM_NCLBUTTONDOWN, HTCAPTION, ...)` で移動へ切り替える。
   → **値の上を掴んでも窓を動かせる。**
3. 動かないまま `WM_LBUTTONUP` が来たらクリックとして処理（コピー／巡回／設定）。

### ホバー

`WM_MOUSEMOVE` で矩形を判定し、離脱は `TrackMouseEvent(TME_LEAVE)` の `WM_MOUSELEAVE` で取る。
カーソルは `IDC_ARROW` のままにする（`IDC_HAND` はハイパーリンクに読める）。
**ホバーの塗りだけでクリック可能を示す。**

## 8. 形式（FR-007 / FR-008）

閉じた集合。`enum class` にする。**`switch` に `default` を書かない**（CPP-002）。

| 順 | チップの表示 | 例（`#FF8000`） | 最長 | 文字数 |
| --- | --- | --- | --- | --- |
| 1 | `RGB` | `255,128,0` | `255,255,255` | 11 |
| 2 | `HEX` | `#FF8000` | `#FFFFFF` | 7 |
| 3 | `CMYK` | `0,50,100,0` | `100,100,100,100` | **15** |
| 4 | `HSL` | `30,100%,50%` | `360,100%,100%` | 14 |
| 5 | `HSV` | `30,100%,100%` | `360,100%,100%` | 14 |

- **区切りは `,`（空白なし）。** 理由は第 2 節。仕様の例（`255, 128, 0`）と表記が変わるので、
  採用するなら SPECIFICATION.md 側も直す。空白付きを保つなら値欄を 150 DIP 以上にする。
- 表示文字列とクリップボードへ入れる文字列は**同じもの**にする（FR-006「その文字列」）。

  キャンバスの `FormatCycle` に描いた150 × 156 DIP・項目高さ28 DIPは96 DPIでの参考図であり、規範値ではない。
- 🔶 FR-008 は仕様上「決め打ちしない」項目。この案は仕様の初期値（トグル＋右クリック）どおり。

### 9.2 常に最前面（hide の追加依頼・2026-09-06）

🔴 **初期値をオンにすることと、再起動後も保持することは hide の指示に無い。**
hide の依頼は「設定で常に最前面のトグルが欲しい」まで。

**適用のしかた**

### 9.3 モーダルとしての挙動（親との整合性）

| 事項 | 決め |
| --- | --- |
| 所有 | `CreateWindowExW` の `hWndParent` にルーペ窓を渡す。オーナー窓なので常にルーペ窓の上に出て、ルーペ窓と一緒に隠れ、一緒に閉じる |
| 入力 | 開いている間は `EnableWindow(loupe, FALSE)`。閉じたら `TRUE` に戻してから `SetForegroundWindow` でルーペ窓へ戻す（この順を守らないと別アプリが前面に出る） |
| **採取** | **止めない。** 30 ms タイマ・`ScreenSamplerPort` の呼び出し・再描画はそのまま続ける。止めるのは入力だけ |
| **最前面属性** | **親と子で必ず同じ値にする。** 親だけ最前面だとモーダルは親より前だが全画面アプリの下へ回り、子だけ最前面だとモーダルが無関係な窓の上へ浮く。トグル操作時は親 → モーダルの順に `SetWindowPos` する |
| 取り込み除外 | モーダルにも `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` を掛ける。「自分の窓は採取に入れない」という ADR 0005 の規則を 2 枚目にも通す。掛けないと、モーダルがレンズに重なったときにモーダル自身の画素を採ってしまう |
| 位置 | ルーペ窓の中央に出し、モニタの作業領域へクランプする |
| DPI | Per-Monitor v2。`WM_DPICHANGED` を親と同じように処理する |
| 閉じる | Esc、✕、Alt+F4。ルーペ窓が閉じるときは先にモーダルを閉じる |
| 二重に開かない | すでに開いていれば新しく作らず、既存のモーダルを前面へ出す |

## 10. GDI での実装メモ

素の GDI で描ける範囲だけで構成してある。追加の依存は要らない。

| やること | API |
| --- | --- |
| 地・チップ・色板・帯の平塗り | `SetDCBrushColor` + `FillRect(GetStockObject(DC_BRUSH))`（現状と同じ） |
| 1 DIP の枠 | `FrameRect`（現状と同じ） |
| 文字 | `CreateFontIndirectW` + `DrawTextW`、`CLEARTYPE_QUALITY`、`SetBkMode(TRANSPARENT)` |
| ▾ | `Polygon` 3 点 |
| ラジオの丸 | `Ellipse` |
| 常に最前面のスイッチ | 軌道が `RoundRect`（36×20、角丸 10）、つまみが `Ellipse`（16 径） |
| 二重バッファ | 既存の `LoupeRenderer::render` のメモリ DC 一括転送をそのまま使う |

**使っていないもの**（意図的）: グラデーション、影、半透明、角丸の窓。
角丸は Windows 11 の `DWMWA_WINDOW_CORNER_PREFERENCE` か `SetWindowRgn` が要り、
対応下限の Windows 10 2004 に合わない。ピクセルを見る道具なので窓の端は直角のほうが基準として役に立つ。

### アイコン

絵文字は使わない。実装では **Segoe MDL2 Assets** の字形を想定する。

| 用途 | 符号位置 |
| --- | --- |
| ギア | `U+E713` |
| チェック（コピー通知） | `U+E73E` |
| 閉じる（設定） | `U+E711` |

⚠️ **未確認**: Windows 10 2004 に Segoe MDL2 Assets が入っている想定だが、実機で確認していない。
入らない場合は `Polygon` / `Polyline` で描く。キャンバスの図はその形（塗りの 8 歯の歯車）で描いてある。

### ポップアップメニューのテーマ

⚠️ `TrackPopupMenu` は **システムのテーマ**で描かれる。アプリのテーマ（FR-010）とは連動しない。
一致させたいならオーナードロー（`MNS_OWNERDRAW` / `MF_OWNERDRAW`）が要る。
キャンバスの `FormatCycle` にはシステムのダーク・ライト両方を並べてある。**どちらで妥協するかは判断事項。**

## 11. 正典経路（どの層に何を置くか）

| もの | 層 | 根拠 |
| --- | --- | --- |

| 描画 | `ui/win32/LoupeRenderer.cpp` | 既存の唯一の描画経路を太らせる |
| ヒット判定・ドラッグ・タイマ | `ui/win32/LoupeWindow.cpp` | |
| `COLORREF` への変換 | `ui/win32` | `core` に Win32 型を持ち込まない |
| クリップボード書き込み | `adapters/win32` + `application` のポート | 外部状態。ARC-007。失敗は閉じた結果型で返す（ARC-010） |
| 設定の保存・読み込み | `adapters/win32` | ARC-007 / ARC-009 / FR-012 |

**窓の表示方式を変える場合（レイヤード窓・透明化・角丸）は、実装前に ADR を書く。**
今回の案はどれも既存の不透明 `WS_POPUP` のままで実現できるので、ADR は要らないはず。
