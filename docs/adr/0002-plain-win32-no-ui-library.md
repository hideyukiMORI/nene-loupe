# ADR 0002 — UI ライブラリを使わず、素の Win32 で作る

- 状態: 受理
- 日付: 2026-09-06
- Issue: #1
- 影響する規則: ARC-003 / ARC-006 / ARC-011

## 文脈

施主の当初案は C++ ＋ WinUI 3 だった。製品は枠なし・ドラッグ可能・初期 160×64 程度の小さなウィジェットで、
左にルーペ（自前描画）、右に色番号、トグルとギアアイコンだけを持つ（SPECIFICATION.md）。

本リポジトリは**実験リポジトリ**であり、第一目的は「厳格な機械強制の規約を C++ に適用できることを public に示す」こと、
道具としての有用性は第二目的である（施主 2026-09-06）。

## 決定

**UI ライブラリを使わない。素の Win32（`WS_POPUP` の窓・`WM_NCHITTEST`・`BitBlt`・`SetClipboardData`・ポップアップメニュー）で作る。
描画は GDI から始め、必要になったら Direct2D を ADR で入れる。**

## 強制

- **planned**: CMake のターゲットグラフで、`core` と `application` が `user32` / `gdi32` をリンクできず、`windows.h` を含められないこと（ARC-003）。規約検査（CNF）で `#include <windows.h>` の場所を限定する
- **不能**: 「UI ライブラリを後から足さない」こと自体。依存の追加は ADR 事項（DEVELOPMENT_WORKFLOW 第 6 節）で担保する

## 結果

得られるもの:

- 単体 exe（数百 KB）、ランタイム依存なし、起動即時。常駐させる小物として正しい重さ
- 憲章の「中核をプラットフォームから独立させる」が守りやすい。WinRT 投影が全域に染みない
- ビルドが速く、診断が読める。規約検査を依存ゼロで書ける

失うもの:

- 標準部品（コンボボックス・ダイアログ・アクセシビリティ）を自前で描く。ただし本製品では標準部品をほぼ使わない
- Mica や角丸などの現代的な見た目は自前（レイヤードウィンドウ）で作る必要がある

正直に記録しておくこと:

- 画面の取り込みは `BitBlt` で、HDR / 広色域の値は扱えない。WinUI 3 でも同じ経路を通るので、この選択の得失ではない
- WinUI 3 を使わない判断は、この規模の製品に対するものである。大きな UI を持つ製品（NeNeCommander）では逆の判断が成り立つ

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| C++ ＋ WinUI 3 | この規模の枠なしウィジェットは WinUI 3 が提供するものをほぼ使わず、逆に枠を消す・ドラッグ領域を宣言する・透明窓が作れない、と標準を殺す作業が主になる。Windows App SDK ランタイム依存・数十 MB のメモリ・0.5〜1 秒の起動は常駐小物に不釣り合い。C++/WinRT ＋ XAML のツールチェーンは診断が読みにくくビルドが遅い。NeNeCommander の analyzer 資産は Roslyn 依存で C++ に転用できない |
| C# ＋ WPF | 枠なし窓は容易で、NeNeCommander の analyzer 資産がそのまま使え最速だが、**本リポジトリの第一目的（C++ を示す）を満たさない** |
| Rust ＋ windows-rs | 規約の機械強制は 6 言語で最強だが、C++ を示す目的に合わない。Win32 FFI の `unsafe` を隔離する設計も別途要る |
| C++ ＋ Qt / wxWidgets | 依存が exe より大きくなる。この製品が使う部品は窓 1 枚とメニュー 1 つで、ライブラリの価値が出ない |
