# ADR 0007 — README のために、除外を外した起動で自分の窓を撮る

- 状態: 受理
- 日付: 2026-09-07
- Issue: #21
- 影響する規則: ARC-001 / ARC-011 / CPP-002 / CPP-012 / CNF-002 / QLT-009
- 補足する ADR: 0005（除外の決定そのものは変えない）

## 文脈

README の先頭に実機のスクリーンショットを置きたい。しかし ADR 0005 により、ルーペと設定窓は
`WDA_EXCLUDEFROMCAPTURE` を掛けている。除外は「一般のスクリーンショットにも映らなくなる」ことを
含めて受理された決定であり、README にもそう書いてある。

どの取得経路が実際に通るのかを、推測ではなく実測した（`out/readme-capture/probe*.py`、
2026-09-07、Windows 11 Pro 26200、製品 HEAD bd7b055 のビルド）。

| 経路 | 結果 |
| --- | --- |
| `PrintWindow(hwnd, dc, PW_RENDERFULLCONTENT)` | 戻り値 TRUE、画像は全面 #000000 |
| `PrintWindow(hwnd, dc, 0)` / `PW_CLIENTONLY` | 戻り値 TRUE、DC に何も描かれない（番兵の色が残る） |
| 画面 DC からの `BitBlt` | 背面だけが写り、窓は写らない（除外の設計どおり） |
| 別プロセスからの `GetWindowDC` ＋ `BitBlt` | `BitBlt` が FALSE |
| 別プロセスからの `SetWindowDisplayAffinity(hwnd, 0)` | FALSE、`GetLastError()` = 5（アクセス拒否） |
| 製品に `WM_PRINTCLIENT` を実装して `PrintWindow` | 効果なし。除外された窓では窓プロシージャに届かない |

最後の行は自作の窓で切り分けた。同じ窓を除外なしにすると、別プロセスからの `PrintWindow` は
0 / 1 / 2 のどの flag でも正しい内容を返し、除外を掛けた瞬間に上表の結果へ変わる。
つまり塞いでいるのはプロセス境界ではなく除外そのものであり、製品側に描画の口を足しても通らない。
`WM_PRINTCLIENT` の実装は測定のうえで捨てた。

除外を外すと今度は別の問題が出る。自作の窓で測ると、除外を外した窓の中心を画面 DC から読んだ色は
背面の #FF8000 ではなく窓自身の #00CC00 になる。ルーペの採取点はレンズ中心（クライアント 32 DIP）で
必ず自窓の内側にあるから、除外を外したまま普通に置いて撮ると、レンズは自分自身を拡大した像になる。

## 決定

**文書化した診断用の起動引数 `--allow-screen-capture` でだけ取り込み除外を外し、撮影時は
ルーペの上に背景の窓を重ねてから `PrintWindow` で撮る。**

- 除外するかどうかは `CaptureExclusion`（`enabled` / `disabled`）という閉じた選択肢にする。
  引数の解釈は `capture_exclusion_of` の 1 か所だけが行い、ルーペ窓・設定窓・メニューの
  3 つはすべて `CaptureExclusionStyle` を通して同じ値を使う（ARC-001）。既定は `enabled`。
- 撮影スクリプト `eng/capture-readme-images.py` は、ルーペを覆う背景窓を最前面に置いてから
  レンズ直下の 7×7 画素を描く。ルーペは自窓ではなくその背景を採取する。
- 撮影は窓が隠れていても通る `PrintWindow(PW_RENDERFULLCONTENT)` で行う。
  隠れた窓でも正しく撮れることは実測した（`probe5-results.json`）。
- 撮れた画像を採用する条件は、**窓自身の題名が、スクリプトが描いた中心画素の HEX と一致すること**。
  一致しない画像は保存しない。自窓を採ってしまった像を README に載せない機械的な歯止めである。
- 合成はしない。README の 4 枚はすべて動いているアプリの窓そのものである。
  `docs/images/social-preview.png` だけは合成物で、実写を 2 倍に拡大して台紙に載せたものである。

## 強制

強制の状態の正本は [QUALITY_GATES.md](../QUALITY_GATES.md) である。本 ADR は規則を足さないので、
どの規則の状態も動かさない。

- `capture_exclusion_of` の解釈は単体テストで固定した（QLT-009 は active、分岐 90% を要求する）。
- `CaptureExclusion` の 2 分岐は `CaptureExclusionStyle` の網羅 switch を通る。
  CPP-002 は planned のままで、実在する補助は `/we4061 /we4062` と `covered-switch-default` である。
- 「撮った画像が自窓の像でないこと」は撮影スクリプトの題名照合が守る。これはゲートではない。
  `eng/check.ps1` は画像を作らないし、検査もしない。README の画像が古くなったことは機械が教えない。
- 引数を渡した起動でレンズが自分を採ることは、仕様どおりの帰結であって欠陥ではない。
  これを機械で防ぐ手段は無い（防ぐには除外を外せなくするしかない）。

## 結果

得られるもの:

- README に実機の写真が載る。除外を外さない普通の起動には何の変化も無い。
- 画像を作り直す手順が 1 本のスクリプトとして残る。DPI・窓の矩形・採取色は
  `out/readme-capture/capture-results.json` に数値で残る。

失うもの・残る穴:

- 製品に、普通の利用者には要らない起動引数が 1 つ残る。これは撮影のためだけの引数であり、
  この ADR がその存在の唯一の根拠である。
- 引数を渡すと 3 種類の窓すべてが取り込みに映るようになる。渡した利用者の画面共有には窓が映る。
- この機械には 100% の表示器が無い。撮れたのは 125%（120 DPI）と 150%（144 DPI）である。
- 画像は撮影時点の版（0.2.0）の見た目であり、UI を変えても自動では更新されない。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| `PrintWindow(PW_RENDERFULLCONTENT)` をそのまま使う（製品変更なし） | 実測で全面 #000000。除外された窓には通らない |
| 製品に `WM_PRINTCLIENT` を実装する | 実装して実測した。除外された窓では `PrintWindow` が窓プロシージャを呼ばないので効果が無い |
| 撮影プロセスから除外を外す | `SetWindowDisplayAffinity` がアクセス拒否。他プロセスの窓には掛けられない |
| 除外を外して、そのまま画面を撮る | レンズが自窓を採る。実測で中心の色が背面ではなく窓自身の色になった |
| 背景と窓を別々に撮って重ねる | 実機のスクリーンショットと呼べなくなる。実測を伴わない主張を書かない規律に反する |
| 製品に撮影機能（画像の書き出し）を足す | 起動引数より重い変更で、製品にファイル書き出しの経路が増える。撮影は製品の仕事ではない |
| README に写真を載せない | 除外は仕様であって、見た目を隠す理由ではない。載せない理由にならない |
